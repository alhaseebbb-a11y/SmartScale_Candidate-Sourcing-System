Candidate Sourcing System

Technical documentation and implementation specification for the SmartSkale recruitment platform. The system centralizes job requisition management, public job discovery, candidate applications, resume collection, and administrator-side application review.

Project Scope

The system provides a responsive web-based career portal and an internal admin console. Public job browsing does not require authentication; authentication is enforced when a candidate begins the application process.

In ScopeOut of Scope — Phase 1
Job creation, editing, draft/publish/closeAI resume parsing and candidate matching
Public job listing and job detailsInterview scheduling
Candidate registration and loginOffer management and onboarding
Bio, education and work experienceLinkedIn/Naukri/Indeed integrations
Mandatory resume uploadBackground verification and assessments
Application status trackingNative Android/iOS applications
Admin application grid and resume reviewMulti-language localization
⚠️

Important: AI/GenAI is deliberately excluded from the Phase 1 implementation. The goal is a complete, reliable sourcing workflow rather than unnecessary complexity.

Authentication & JWT

The backend uses JWT access tokens for stateless authentication and role-based authorization. Passwords are hashed before persistence and never returned in API responses.

JWT Payloadexample
{
  "sub": "candidate-user-uuid",
  "role": "CANDIDATE",
  "type": "access",
  "iat": 1787500000,
  "exp": 1787501800
}
LayerImplementation
Password hashingbcrypt or Argon2
Access tokenShort-lived JWT
Refresh tokenLonger-lived JWT or secure token record
Protected routesFastAPI Depends(get_current_user)
Admin authorizationDepends(require_admin)

Candidate Application Module

Step 1 — Bio

First name, last name, email, mobile and current location are mandatory. Gender, date of birth, current company, notice period, address and profile photo are optional.

Step 2 — Education

One or more education records can be added. Degree, institution, year of passing and education level are required.

Step 3 — Work Experience

One or more work experience records can be added, or the candidate can select Fresher. Total experience can be derived for admin filtering.

Step 4 — Resume & Submit

RequirementRule
ResumeMandatory; PDF/DOC/DOCX; recommended max 5 MB
Cover NoteOptional; maximum approximately 500 words
Data AccuracyMandatory checkbox
Privacy PolicyMandatory checkbox
SubmitDisabled until resume and both consent checkboxes are valid

Authentication APIs

POST/api/v1/auth/registerCreate candidate account

No authentication required.

{
  "first_name": "Rahul",
  "last_name": "Sharma",
  "email": "rahul@example.com",
  "password": "StrongPassword123"
}
POST/api/v1/auth/loginAuthenticate candidate/admin
{
  "email": "rahul@example.com",
  "password": "StrongPassword123"
}

Returns an access token and refresh token.

GET/api/v1/auth/meCurrent authenticated user

Requires Authorization: Bearer <access_token>.

Job APIs

GET/api/v1/jobsPublic published jobs

Supports search and filters such as ?search=developer&location=Bengaluru.

GET/api/v1/jobs/{job_id}Public job detail

Returns a published job and its public details.

POST/api/v1/admin/jobsCreate requisition

Admin JWT required. Creates a draft by default.

PATCH/api/v1/admin/jobs/{id}/publishPublish requisition

Admin JWT required. Sets status to PUBLISHED and assigns posted date.

PATCH/api/v1/admin/jobs/{id}/closeClose requisition

Admin JWT required. Closed jobs disappear from public listing.

Application APIs

POST/api/v1/jobs/{job_id}/applicationsSubmit application

Candidate JWT required. Uses multipart/form-data because resume upload is mandatory.

candidate data
education records
experience records
resume: PDF / DOC / DOCX
cover_note: optional
consent_accuracy: true
consent_privacy: true
GET/api/v1/candidate/applicationsCandidate's own applications

Returns only applications owned by the authenticated candidate.

GET/api/v1/admin/jobs/{job_id}/applicationsAdmin application grid

Admin JWT required. Supports search, pagination and status filtering.

PATCH/api/v1/admin/applications/{id}/statusUpdate application status
{
  "status": "SHORTLISTED"
}

Security Requirements

AreaRequirement
PasswordsHash with bcrypt/Argon2; never store plaintext.
JWTUse signed, expiring tokens with user ID and role.
AuthorizationEnforce candidate/admin access server-side.
OwnershipCandidates may only access their own applications/profile.
Resume filesValidate extension, MIME type and size; use generated server-side names.
SecretsKeep JWT secret, DB credentials and SMTP credentials in environment variables.
CORSAllow only configured frontend origins.
ErrorsDo not expose stack traces or sensitive database information.

Validation & Business Rules

1
Published jobs onlyAnonymous job APIs return only PUBLISHED requisitions.
2
Login before applicationUnauthenticated visitors are redirected to Login/Register.
3
Resume mandatorySubmission is rejected without PDF/DOC/DOCX resume.
4
Consent mandatoryBoth data accuracy and privacy consent must be accepted.
5
Duplicate preventionDatabase enforces UNIQUE(job_id, candidate_id).
6
Status controlApplications use NEW, REVIEWED, SHORTLISTED or REJECTED.
